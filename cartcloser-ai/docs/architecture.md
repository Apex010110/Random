## Why two engines?
The MRD requires a demo that never depends on the network. The **offline engine** (`flutter_app/lib/core/engine/`) is a line-by-line port of the backend services. Both read the same seed files and are checked by `test/parity_test.dart`, which replays 384 questions through the Dart assistant and compares intent, language, action, confidence and exact text with fixtures generated by the Python engine (`backend/scripts/make_parity_fixtures.py`). The UI uses only the repository interface, so switching between Offline and Backend in Settings changes nothing visible.

## Cart status machine
```
active_cart ─checkout-started─▶ checkout_started ─abandon (explicit event)─▶ abandoned
abandoned ─eligibility()─▶ not_eligible(reason) | eligible ─▶ scheduled (delay) ─deliver()─▶ message_sent
message_sent ─shopper reply─▶ replied ─unknown/human intent─▶ human_handoff
contacted states ─order placed within window─▶ recovered      ─window passes─▶ expired
any ─STOP / revoke─▶ opted_out            checkout_started/scheduled ─order without contact─▶ ordered
```
`eligibility()` runs at abandonment **and again at send time**: already purchased → cancel; no active consent → `no_consent` / `opted_out`; under-18 → `under_18_safeguard`; campaign/cart paused; contact cap; empty cart. Quiet hours defer (not drop) the send. The send itself is an atomic `UPDATE … WHERE status='scheduled'`, so two schedulers cannot double-send.

## Consent model
`ConsentRecord(channel, purpose=checkout_reminders, granted, consent_version, consent_text, source, created_at, revoked_at)`. Created only by an explicit affirmative action (unchecked checkbox at checkout, or the preferences dialog). A phone number is never consent. STOP (any language variant) revokes immediately and cancels scheduled sends.

## Assistant pipeline
1. Sanitize (strip NUL / bidi overrides, 500 char cap) → detect language (Urdu script / Roman Urdu markers / English).
2. Detect intents (priority: opt-out > injection guard > human > discount > COD > shipping > delivery > returns > size > stock > link > thanks > greeting).
3. Compute the answer **only** from catalog, stock, policy, delivery windows (business days, Sunday off) and settings. Unknown → human handoff (confidence 0.2).
4. Optional: `ai/provider.py` asks Claude (`AI_MODEL`, default `claude-opus-5-5`, low effort, server-side refusal fallbacks) to *rephrase* the grounded text. The output is discarded if it introduces any number not in the facts, drops the no-guarantee wording, contains Devanagari, is empty/long, refused or times out. Actions (opt-out, handoff, discounts) are never delegated to the LLM.

## Metrics
Computed on every request from stored rows (`services/metrics.py`, mirrored in Dart). Definitions are returned with the payload and shown in the dashboard. Attributed sales = completed order totals placed after a recovery contact inside the attribution window (default 7 days), one attribution per order. Incremental lift is "Not measured" until a randomized holdout has ≥30 carts per arm.
